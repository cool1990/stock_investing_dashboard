- 要回答什么问题；
- 页面结构；
- 数据来源；
- 数据模型；
- 计算口径；
- 交互方式；
- 注意事项；
- 验收标准。

## 在 Cursor 里怎么说

第一次对话：

> 先完整阅读 docs/00_README.md 和 docs/01_common.md，再浏览 docs/02–08 的标题结构。不要写代码，先给我一份实施计划，包括：阶段划分、每阶段要创建的文件、你认为规格里有矛盾或不清楚的地方。

确认计划后，按阶段推进：

> 执行阶段 P0（见 01_common.md 第 9 节）。完成后停下，列出完成项、与设计稿的差异、遗留问题。

之后每一页单独推进：

> 按 docs/04_financials.md 实现财务报表页，包括数据管道和页面。完成后按该文件的「验收清单」逐项自查并报告结果。

## 推进顺序（建议）

1. **P0**：全站外壳加 7 个页面的静态还原，先用样例数据，暂不接数据管道。
2. **P1**：财务报表（`04`）。它的数据最结构化，也是其他页面的基础。
3. **P2**：分析师预期（`06`），包括每日共识快照，**越早开始积累越好**。
4. **P3**：股价反应（`07`）和财报解读的数字部分（`03`）。
5. **P4**：电话会（`05`）和财报解读的 AI 部分（`03`）。
6. **P5**：观察池（`02`）的公告、日历和汇总。
7. **P6**：数据说明（`08`），以及运维和告警。

## 每次财报后的 AI 处理（手动模式）

网站的抓取和计算全部在 GitHub Actions 中自动完成。只有 AI 解读部分需要你在 Cursor 里触发一次，用的是 Cursor 自带的额度，不需要任何 API 密钥。

有新任务时，仓库会自动开一个 Issue 提醒你。你只需要 `git pull`，然后在 Cursor 里说：

> 处理 ai/tasks/ 下所有还没有对应输出的任务：逐个读取任务包，严格按其中的 prompt 和 schema 生成 JSON，写到指定的输出路径。完成后运行 `python scripts/ai_check.py`，修正所有报错，直到全部通过，然后 commit 并 push。

详细流程见 `01_common.md` 第 7.5 节。以后如果想全自动，在 `config/ai.yaml` 里把 `provider` 改成 `deepseek`，再配置好密钥即可。

## 写给 Cursor 的总原则

- 规格写明的就照做。规格没有写到的，先提问，不要自行假设。
- **数字诚实**：缺失的数据显示为占位符（`[ ]`、`不可得`、`未披露`），不能编造、插值，也不能用另一个来源的数默默顶替。
- 每完成一页，都要按该页的验收清单自查。
